## 🔍About the project

Tennis Match Scoreboard is a Java web application for tracking tennis match scores in real time and storing completed match results in a PostgreSQL database.

The project implements tennis scoring logic, including points, games, sets, and tie-breaks. 
It also provides an API for creating matches, updating scores, retrieving current match results, and browsing completed matches.

The application was built to deepen my understanding of Java web development, Spring MVC, Jakarta Servlets, Hibernate ORM, database integration, and application architecture.

## 💿Prerequisites & Installation

### Prerequisites

- **JDK 21**
- **PostgresSQL**
- **Maven**
- **Tomcat 10**

### 🔁Local Setup

1. Clone the repository:

   ``` bash
   git clone https://github.com/PronovichV1/tennis-scoreboard.git
   cd tennis-scoreboard
   ```

2. **Build the project using Maven**

    ``` bash
   mvn clean package
   ```

3. **Deploy the application to Tomcat:**

- Navigate to `tennis-scoreboard/target/` and copy `tennis-scoreboard-1.0.0.war`.
- Paste it into your Tomcat `webapps/` directory.

4. **Start Tomcat:**

- Execute the startup script from the Tomcat `bin/` directory:
- **Linux / macOS:** `./bin/startup.sh`
- **Windows:** `bin/startup.bat`

5. **Access the application** - the app will be available at: http://localhost:8080/tennis-scoreboard

### 🔁Remote Deployment

1. **Clone the repository**
   ``` bash
   git clone https://github.com/PronovichV1/tennis-scoreboard.git
   cd tennis-scoreboard
   ```

2. **Build the project using Maven**

    ``` bash
   mvn clean package
   ```

3. **Prepare the server:**
   Be sure your server has `JDK 21`,`Tomcat 10/11`,`PostgresSQL`.
   Be sure `Tomcat 10/11` has all needed permissions.

4. **Download `.war` file on server:**

   Upload the compiled file to the webapps folder of your Tomcat (via password or SSH key):
    ``` bash
   scp target/tennis-scoreboard-1.0.0.war <username>@<your-server-ip>:/opt/tomcat/webapps/
   ``` 
5. **Start Tomcat:**

   If Tomcat is not already running, run on the server:
    ``` bash
   /opt/tomcat/bin/startup.sh
   ```

6. **Access the application** - the app will be available at: `http://<your-server-ip>:8080/tennis-scoreboard-1.0.0`.

## 🗃️Database Schema

**Database Schema**:
The application uses PostgreSQL with the database `tennis_score_board`.

**Tables**

`players` - stores players records.

`matches` - stores completed matches, including references to both players and the match winner.

**Data Persistence**

Active matches are maintained in memory while the game is in progress. 
Match results are persisted to PostgreSQL after the match is completed.

### 🛑Limitations

- the id in `players` is unique;
- `players` is linked to `matches` via foreign keys.
- for practice with multithreading all non-finished matches stored in memory.
- matches save in database only after end of the match.
- active matches may be lost if the application restarts before the match is completed.

## 🔌Endpoints examples

### 1. Create a Match

`POST /matches`

**Request Body** (`Content-Type: application/json`)

```json
{
  "firstPlayerName": "First Player",
  "secondPlayerName": "Second Player"
}
```

**Response:**

**201 Created** - Success response. The JSON contains autogenerated `uuid` for the match. 

```json
{
   "id": "1d5e5fb4-5203-4933-8278-486f3d8db2ca"
}
```

### 2. Score Point & Get Current Score

`POST /matches/{uuid}/point`

**Path Parameters:**
- `uuid` — Unique identifier of the match.

**Request Body** (`Content-Type: application/json`)

```json
{
  "name": "First Player"
}
```

**Responses:**

**200 OK** — Success response. The JSON contains nested objects `firstPlayer` and `secondPlayer`, describing the score for each player.

Example 1 — Regular Game:

```json
{
   "firstPlayer": {
      "name": "First Player",
      "points": 40,
      "games": 2,
      "sets": 0,
      "tieBreakPoints": null
   },
   "secondPlayer": {
      "name": "Second Player",
      "points": "AD",
      "games": 3,
      "sets": 1,
      "tieBreakPoints": null
   },
   "winnerName": null
}
```

Example 2 — Tie-Break:

```json
{
   "firstPlayer": {
    "name": "First Player",
    "points": 40,
    "games": 2,
    "sets": 0,
    "tieBreakPoints": null
  },
  "secondPlayer": {
    "name": "Second Player",
    "points": "AD",
    "games": 3,
    "sets": 1,
    "tieBreakPoints": null
  },
  "winnerName": null
}
```

**Error Codes:**

- `404 Not Found` — Match with the specified UUID was not found.

### 4. Completed Matches List

`GET /matches`

**Query Parameters:**
- `page` — Page number (optional).
- `player_name` — Player name used to filter matches (optional).

**Responses:**

**200 OK** — Success response.

```json
{
  "matches": [
     {
        "firstPlayerName": "First Player",
        "secondPlayerName": "Second Player",
        "winnerName": "Second Player"
     },
     {
        "firstPlayerName": "First Player",
        "secondPlayerName": "Second Player",
        "winnerName": "First Player"
     }
  ],
   "currentPage": 0,
   "totalPages": 10
}
```
